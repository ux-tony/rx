# STATUS — RX Architect Portfolio

_Сводка для контроля проекта. Обновлено: 2026-07-05._

## 1. Что это за проект

Минималистичный сайт-портфолио для архитектурной студии (**«Roman Kharchenko Studio»**). Frontend-MVP в журнальном стиле: главный экран (hero), сетка проектов, услуги, FAQ и контактный блок. Референс дизайна — zrobim.ru (см. `task.md`): крупные изображения проектов, много «воздуха», минимум UI, светлый фон, один акцентный цвет.

## 2. Стек и структура

- **Next.js 15** (App Router) + **React 19** + **TypeScript**
- **Mantine 7** — UI-библиотека (использовать точечно: формы, FAQ)
- **Sanity 4** (`next-sanity`) — headless CMS, встроенная Studio на `/studio`
- Стили — собственный CSS (`app/globals.css`, `app/studio.css`), без Tailwind

Ключевые директории:

- `app/(site)` — публичный сайт (`page.tsx` — главная, единственная страница)
- `app/(studio)` — встроенная Sanity Studio
- `components/` — секции и UI (hero, projects, faq, services, contact-strip, discussion-modal и т.д.)
- `data/site-data.ts` — mock-данные (проекты, услуги, FAQ, метрики) — fallback
- `lib/sanity/` — клиент, GROQ-запросы (`queries.ts`) и загрузчики (`get-*.ts`)
- `sanity/schemaTypes/` — схемы контента (hero, projects, services, faq, project, service, category и секции)
- `sanity/mock-content.ts` + seed-tool — импорт демо-контента в Sanity

- Проект **рабочий как MVP**: главная страница собрана, адаптивная, отрисовывается на mock-данных.
- **CMS-интеграция подключена**: `.env.local` заполнен (`NEXT_PUBLIC_SANITY_PROJECT_ID=ppmsri57`, dataset `production`). Все секции читают контент из Sanity, а при пустом ответе аккуратно откатываются на mock-данные (`data/site-data.ts`).
- Studio доступна на `/studio`, вход — через аккаунт Sanity (см. `admin-access.md`).

## 6. Риски и заметки

- **Секреты в репозитории:** `.env.local` закоммичен и содержит `projectId`. Сам по себе public project ID не критичен, но `.env.local` не должен попадать в git — проверить `.gitignore`. Токенов записи в Sanity в коде нет (клиент `useCdn:false`, только чтение) — это хорошо.
- **Один автор, «bus factor = 1»**: весь код и контент завязаны на одного разработчика (kupko / tony.kupko@gmail.com).
- **Зависимость от Sanity-аккаунта:** доступ к CMS — через личный аккаунт Sanity. Стоит зафиксировать владельца проекта и участников.
- **Пауза ~2,5 месяца:** перед продолжением стоит переустановить зависимости и убедиться, что сборка проходит на текущих версиях Next 15 / React 19 / Sanity 4.
- Проект **не содержит тестов** — регрессии ловятся только вручную.

## 7. Рекомендуемые следующие шаги

1. Локально поднять проект: `npm install` → `npm run dev`, открыть `/` и `/studio`, убедиться, что всё работает после паузы.
2. Прогнать `npm run typecheck` и `npm run build` — зафиксировать, что ошибок нет.
3. Проверить `.gitignore` и при необходимости убрать `.env.local` из индекса git.
4. Определить и загрузить реальный контент в Sanity (проекты, фото, тексты, контакты).
5. Уточнить логику формы «Обсудить задачу»: куда уходят заявки.
6. Настроить деплой (например Vercel) и переменные окружения на хостинге.
7. Зафиксировать владельца/доступы Sanity, чтобы проект не зависел от одного аккаунта.
